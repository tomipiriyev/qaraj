# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Qaraj — marketing landing page for an Airbnb-style marketplace for unused storage space (garages, basements, spare rooms, warehouse corners, parking, lock-ups). Users can rent by the square meter, by item type (the page suggests needed m²), or rent a full space, monthly or yearly.

**The site is localized for the Russian market.** All visible copy, meta tags, JSON-LD, `llms.txt` and `ai.txt` are in Russian (`<html lang="ru">`); the brand name stays "Qaraj" (Latin). Prices are in ₽ (rubles) throughout — including the calculator's `pricePerSqm` constant — and example cities/names are Russian (Москва, Санкт-Петербург, Казань). Keep new copy in Russian and prices in ₽. See [neighbor-ru-seo-geo-todo.md](neighbor-ru-seo-geo-todo.md) for the SEO/GEO plan this localization follows (only the front-end items are implemented).

**Product model (three categories).** The product behind the landing page organizes spaces into **three categories: Склад (storage — a whole closed space, priced per space), Площадь м² (area — part of a larger space, priced per m², with the item-type → m² calculator), and Гараж (garage — priced per space, sized by car).** Note **Гараж replaces an earlier "Парковка/parking" category.** All three share five facility amenities (climate control, camera monitoring, 24/7 access, smoke detector, electricity). The buildable app spec lives in [MVP.md](MVP.md) (v1 = inquiry/match only, native mobile, RU-hosted backend), and an interactive Figma prototype (*Qaraj — App UI*, Airbnb-style) models the renter flow Home → Search → Date → Map → Filter. Keep landing-page category copy consistent with these three.

## Architecture

The landing page is a single self-contained static page: [index.html](index.html). There is no build step, package manager, framework, or test suite — open the file directly in a browser to view it.

**SEO landing pages (added for organic search).** Alongside `index.html` there are six standalone SEO pages, each at `/<slug>/index.html` so the URL is a clean directory (`/arenda-garazha-moskva/`, `/arenda-kladovki-moskva/`, `/hranenie-veshchey-moskva/`, `/sdat-garazh-v-arendu/`, `/dogovor-arendy-garazha/`, `/skolko-stoit-arenda-garazha/`). Unlike `index.html`, these **share an external stylesheet** [styles/page.css](styles/page.css) (tokens mirror `index.html`'s `:root` — change both together) and are **generated by a Python script**, not hand-edited: [tools/gen_pages.py](tools/gen_pages.py) holds all page copy and writes the `.html` files (run `python3 tools/gen_pages.py` from the repo root — no dependencies). To change a page's copy, edit the generator and re-run it rather than patching the HTML by hand, or the next regen will overwrite your edit. Each page carries its own `BreadcrumbList` + `FAQPage` JSON-LD (FAQ JSON-LD mirrors the visible `<details>` list — keep in sync), an inline SVG data-URI favicon, and links back to `index.html` section anchors (`/#waitlist`, `/#owners`, `/#how`, `/#faq` — note `#waitlist` is the hero section id). The `/dogovor-arendy-garazha/` page has a small copy-to-clipboard script for its contract template. When adding a page, also add it to [sitemap.xml](sitemap.xml), the footer link columns in both `index.html` and the generator's `FOOTER`, and the "Справочные материалы" list in [llms.txt](llms.txt). These pages target real Yandex Wordstat demand (garage/kladovka/storage rental, mostly Moscow-geo and contract/price intent); item-type queries have near-zero volume, so don't build SEO pages around the calculator.

**Articles (30 standalone pages).** Alongside the six SEO landing pages there are 30 article pages, each a **standalone page at `/<slug>/` in the site root** — there is deliberately **no `/blog/` index page and no blog hub**; articles are reached through the "Читайте также" block, the footer, and search. They are built by [tools/gen_blog.py](tools/gen_blog.py) from content in [tools/blog_posts.py](tools/blog_posts.py) — run `python3 tools/gen_blog.py` from the repo root. As with the SEO pages, **edit the content module, not the generated HTML.** Articles are structured data, not raw HTML: each has `title` (the part before the colon — also the footer link text), `subtitle` (the part after), `cluster`, `status`, `desc`, `lede`, `sections` (blocks of `p`/`h3`/`ul`/`ol`/`table`/`amenities`), `faq` and `related`; the block format is documented at the top of `blog_posts.py`. Each article carries `BreadcrumbList` + `FAQPage` + `Article` JSON-LD. `gen_blog.py` also rewrites the article section of [sitemap.xml](sitemap.xml) between the `blog:start` / `blog:end` marker comments — don't hand-edit inside those. (The module and marker names still say "blog" for historical reasons; the output is plain root-level pages.)

Because articles share the root namespace with the landing pages, **a new article slug must not collide with an existing root directory** (`arenda-garazha-moskva`, `styles`, `images`, `app`, …). Nothing enforces this — check before adding.

Articles carry a `status`: `ready` means demand is backed by the Wordstat pulls in `yandex_analysis/`; `draft` means it is not. The 5 `parkovka` articles are a known mismatch — that category was retired from the product in favour of Гараж, so they point at Гараж as the nearest offer; the `pvz` cluster has no Wordstat backing yet. See [blog-titles.md](blog-titles.md) for per-article status and the open decisions.

**Shared chrome.** The header and footer used by both generators live in [tools/chrome.py](tools/chrome.py) (`HEADER`, `FOOTER`, `AMENITIES`, `LOGO_SVG`, `FAVICON`, `FONTS`, `SOCIALS`, plus the `faq_jsonld` / `crumbs_jsonld` / `faq_html` helpers). `gen_pages.py` and `gen_blog.py` both import it, so the footer has one source — **except `index.html`, whose footer is hand-maintained and must be edited alongside `FOOTER`.** The footer lists every article, grouped by cluster, via `chrome.blog_columns()`; it is the main discovery path now that there is no index page. Note `crumbs_jsonld` takes `*trail` pairs of `(name, url)` and always prepends «Главная».

**Footer styling** deliberately follows Airbnb's footer rather than the site's own design system: light `#f7f7f7` ground, `#222` text, 15px Inter (not Sora), no border radius, columns instead of pills. It is the one place where the brand tokens don't apply — keep `styles/page.css` and the copy inside `index.html`'s `<style>` block in sync.

Everything else lives in `index.html`:
- **CSS** is a single `<style>` block in `<head>`. The design system is driven by CSS custom properties on `:root` (`--brand`, `--brand-2`, `--brand-deep`, `--accent`, `--bg-*`, spacing/radius/shadow tokens). The current theme is green. Change brand colors and shared styling there rather than in individual rules — but note a rebrand also requires updating hardcoded `rgba(...)` glow/shadow values scattered in rules (button shadows, `.logo-mark`, `.opt.active`, `.step .num`, the `.hero-bg` gradient overlay), since those mirror `--brand` but aren't tokenized.
- **Layout** is a sequence of `<section>` blocks (hero, three ways to book, categories, featured-spaces marquee, how it works, why choose, owners + calculator, reviews, FAQ, CTA, footer), each anchored by an `id` used for in-page nav links.
- **Responsive** behavior is handled by `@media` breakpoints at the bottom of the style block (~980px and ~560px). On mobile the hero photo layer (`.hero-bg`) is hidden and `.hero-right` gets its own single-image background instead.
- **Interactivity is mostly CSS-only.** Two pieces are pure CSS animation (no JS): the **hero background slideshow** (`.hero-bg` holds stacked `.hero-slide` layers; the `heroFade` keyframes + staggered `animation-delay` per `:nth-child` crossfade through them) and the **featured marquee** (`.marquee-track` auto-scrolls via the `marquee-scroll` keyframes — its slides are duplicated in the HTML and it translates by `-50%`, using per-slide `margin-right` rather than flex `gap` so the loop is seamless). Both respect `prefers-reduced-motion`.
- **Vanilla JS** lives in one `<script>` before `</body>` and now drives *only* the storage-size calculator in the "For owners" section: clicking an `.item-opt` sets the base m² (`data-sqm`), the `#qty` range slider applies a sub-linear multiplier, and it live-updates `#sqmOut` / `#priceOut`. Estimated price is `sqm * pricePerSqm` where `pricePerSqm` is a placeholder constant in that script.
- **Hero phone mockups** are CSS-built (`.phones` > `.phone.left` / `.phone.right`), fanned into a V via `rotate()` + `transform-origin: bottom center`; the screens are fixed-height with `overflow:hidden` (content is intentionally clipped, never stretches the frame). The cluster is positioned with a `translateX` percentage on `.phones`.
- **Icons** are inline SVG. **Fonts** are Sora + Inter loaded from Google Fonts.

## Things to know

- All photography is served from the local `images/` folder (hero slideshow, image-backed category tiles, the "why choose" visual, the phone-mockup listing thumbnails, and the featured marquee). Filenames contain spaces, so references are URL-encoded (`%20`). No remote image dependencies.
- The calculator's `pricePerSqm` and the per-item `data-sqm` values are placeholders; tune them to real pricing.
- All nav, CTA, and footer links are placeholder anchors (`#` or in-page `#section`); there is no backend or routing.
- **SEO/GEO assets:** the `<head>` carries four JSON-LD blocks (`Organization`+`AggregateRating`, `WebSite`, `BreadcrumbList`, `FAQPage`) plus Open Graph/Twitter meta. Root files `llms.txt`, `ai.txt`, `robots.txt`, `sitemap.xml` support AI/search crawlers. The `FAQPage` JSON-LD must stay word-for-word in sync with the visible FAQ section — edit both together.
- Canonical/OG/schema/sitemap/robots all use the placeholder domain `https://qubiq.example/` — replace with the real domain before launch.
